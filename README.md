# AF-DecalFinder

## 1.8.3：画像から直接番号編集・枠線幅（現在版）

起動：[AF-DecalFinder.exe](bin/Release-1.8.3/AF-DecalFinder.exe)。`./Build-Viewer.ps1` でReleaseを生成する。実行環境は1.8.2と同じ。

### 画像Ctrl＋ダブルクリックで修正

右の拡大画像でCtrl＋左ダブルクリックすると、統一UI矩形の最寄り中心から固定IDを特定し、クリック位置付近に番号編集ダイアログを表示する。未認識は空欄、認識済みは現在値を全選択。数字・英字・ひらがな等を入力し、Enter/OKで確定、Esc/キャンセルで取消。空欄・空白のみ・制御文字は確定できない。ダイアログは対象モニタの作業領域内に補正する。

- 未認識のみ表示 → Ctrl+A → 正しいラベルを画像で直接修正 → 残った誤検出を一覧で一括削除、という流れで使用する。
- 編集開始と取消では番号・選択集合・キャッシュを変更しない。OK時は対象の固定IDのみ更新・選択解除し、他の選択を維持して再ソート・自動保存する。未認識フィルタ中は修正した行が消える。パン・倍率は維持。
- 認識済みでフィルタに隠れたレコードも直接編集できる。ダブルクリック編集は全アクティブレコードを対象にし、Ctrl単クリック反転は従来どおり表示行だけを対象にする。
- Ctrl単クリックの反転は、OSのダブルクリック判定時間だけ保留する。2回目のMouseDown（Clicks=2）で反転を取り消し、ドラッグでないMouseUpで編集する。2回目をドラッグしても誤編集・反転しない。通常左クリックの逆引きと通常ドラッグは従来どおり。
- LVドッキング/フローティング双方で使用可能。LV編集・検索Enter・LV選択パン・済みチェック・確認付き論理削除を維持。

### 枠線幅

上部の「枠線幅」で **1 / 2 / 3 / 4 px** を選択する。初期値は2px。検索赤枠・選択青枠を両ビュー共通の画面pxで描画し、変更時は即時再描画する。倍率やDPIの倍率を線幅に掛けない。表示範囲の青い破線は従来の2px。

`%LOCALAPPDATA%/AF-DecalFinder/Settings.json` の `FrameWidthPx` に選択値を即時保存・次回復元する。既存履歴・ウィンドウ情報・未知フィールドを保持して一時ファイル経由で安全に置換。未設定/範囲外/不正型の線幅は2pxを使用。書込失敗は通知し、表示の変更は維持する。元bbox・統一UI矩形・ヒット領域・済み50%黒矩形は変えない。

## 1.8.1：代表○サイズ・統一矩形・未認識フィルタ（旧版の記録）

### 統一矩形

OCR元bbox・信頼度は変更せず、実測○中心/寸法と手動クリック座標を補足情報として保持し、UI用矩形を別に計算する。赤枠・青枠・済み50%黒矩形・逆引きの4機能は同じ矩形を使う。手動追加はクリック位置、OCR候補は実測○中心、○情報がなければ元bbox中心を使用。画像端でクリップし、重なる矩形はクリック点から中心が最も近いものを優先する。完全同距離は固定ID順。

代表サイズは実測○候補の幅/高さの中央値を求め、各中央値の±30%以内を残した平均。文字bboxや手動追加はサイズ推定に混ぜない。5件以上、残存率50%以上、幅/高さの変動係数20%以下を信頼条件とし、満たさなければ元bboxへフォールバックする。サイズ外れ値も検出レコードから削除しない。従来の見えない5pxヒット拡張は廃止し、Fitビューも矩形内の最寄り中心を選ぶ。

8画像の推定幅/高さは、テムジン300dpi **30.93px**、600dpi **63.99px**、RGルージュ **53.64px**、カトキガンダム **59.97px**、MGUC **68.71px**、RG RX-78-2 **55.68px**、RX-78 ver3.0 **23.49px**、ルナマリアザク **70.65px**（今回の円候補は幅=高さ）。算出対象数・時間・閾値比較は[評価レポート](Evaluation181/REPORT.md)を参照。

### 未認識の修正操作

- 上部の **未認識のみ表示** をONにすると、内部の未認識フラグがある行だけ表示する。通常文字列として入力した `?` は対象外。フィルタでデータは削除されない。
- フィルタ中も画像逆引き・F2/ダブルクリック編集・Delete/右クリック削除・済みチェックを使用できる。編集が確定するとその行は未認識一覧から外れ、青枠選択も解除する。他の選択行は固定IDで維持する。
- 切替ではパン/倍率を変えない。隠れる行の選択は解除し、表示され続ける行の選択を維持する。OFFで全件を通常順に表示。Ctrl+Aは表示中の行を選ぶ。
- 検索は常に全レコードを対象にし、フィルタ中もEnterで先頭一致へ移動する。認識済みレコードを画像から逆引きした場合と手動追加を確定した場合は、フィルタを解除して対象行を表示する。右ビューの逆引きではパンしない。

## 1.8.0：○候補検出とOCR修正ワークフロー（旧版の記録）

起動：[AF-DecalFinder.exe](bin/Release-1.8.0/AF-DecalFinder.exe)。有効な既存キャッシュはそのまま復元する。既存画像で改善版OCRを試す場合は **ファイル → OCRを再解析…** を使う。画像別キャッシュを手作業で削除する必要はない。

### 修正と貼付作業の操作

- OCRで読めなかった○も固定ID・矩形を持つ未認識レコードとして残し、一覧末尾に `?` を表示する。画像クリックで逆引きできる。未認識状態は通常の文字列 `?` と内部で区別し、通常検索には一致しない。
- F2は先頭選択行、ダブルクリックはクリック行を編集。既存文字列を全選択し、未認識は空欄で開始する。Enterで確定、Escで取消。数字・英字・ひらがな・混在文字列に対応し、全半角・大小文字を変換しない。空欄・制御文字は確定できない。
- 編集後は固定IDと選択を維持して再ソートし、画像位置・倍率を変えない。数値のみ → 英字を含む → その他の文字列 → 未認識の順。文字列比較はOrdinal、数値は桁数制限なし。同値はY、X、固定IDの順。`04` と `4` の表記は維持する。
- 検索欄も文字列の完全一致。入力中は赤枠だけを更新し、Enterで一覧順の先頭一致へパンする。LV選択・Ctrl/Shift/Ctrl+A・逆引き・青枠・ドッキング/フローティングは従来どおり。
- 誤検出は1件または複数件を選び、Deleteまたは右クリックの **誤検出として削除**。件数を確認して確定する。取消時は変更しない。論理削除したレコードは一覧・検索・逆引き・枠・済み集計から除外する。削除取消用のUIは今回追加していない。
- 番号追加も文字列に対応。右画像の位置クリック → 入力 → 確定で独立した固定IDを付与する。済みチェックは従来の1件単位・50%黒表示。修正・追加・削除・済み変更は自動保存する。

### キャッシュの互換性と再解析

- 保存先・パスキー・UTC更新日時・寸法・ファイルサイズの検証は従来どおり。schema 1を変更せず読み込み、次の保存時にschema 2へ安全に更新する。旧ファイルはバックアップとして保持する。
- schema 2は `IsUnrecognized`、`IsDeleted` と元画像のSHA256を追加する。固定ID・OCR元値・手動修正・追加・済み状態を別に保持する。通常のキャッシュ有効性判定を内容ハッシュ判定に置き換えていない。
- 再解析前に旧データを退避する。パス/寸法が一致し、保存時のSHA256と現在の画像バイト列が同一と確認できる場合だけ、修正・追加・削除・済みレコードを元のIDで保持し、重なる新候補を抑止する。削除済み誤検出の同位置での復活を防ぐ。未修正のOCR候補は更新する。
- 内容が変わった画像やハッシュのない無効旧キャッシュには自動で座標を引き継がない。退避先を通知し、旧データを保持する。位置照合は矩形重なりと中心距離によるため、将来の検出方式で位置が大きく変わった候補まで同一と保証するものではない。

### キャッシュと解析中の操作

- `%LOCALAPPDATA%\AF-DecalFinder\Cache\` を継続使用。絶対パスの大文字化UTF-8 SHA256をファイル名とし、内部のパス・UTC最終更新日時・Width/Height・ファイルサイズを検証する。内容が同じでも更新日時が違えば再解析する。

- 無効キャッシュは解析前に `.stale-日時-GUID.json` へ同じバイト列を退避する。退避できなければ上書きしない。新解析成功時は一時ファイルをFlush後、File.Replace（旧内容の `.bak` を保持）で安全に保存する。旧編集内容の座標引継ぎは行わない。解析失敗でも旧ファイルを削除しない。

### 操作

- 一覧のチェックボックスをクリックすると、その検出1件を貼付済み／未完了に切り替える。複数選択中でも1件だけが対象。Spaceによるチェック変更は抑止する。Ctrl＋A、Ctrl/Shift複数選択は維持。

- フローティング中も同じ一覧・追加ボタンを使う。追加中は別窓を隠し、終了時に元のドッキング状態へ戻す。検索赤枠、選択青枠、クリック逆引き、2ビュー連動を維持する。

### 保存と復元

保存先は `%LOCALAPPDATA%\AF-DecalFinder\Cache\`。絶対画像パス（大文字小文字を同一視）のSHA256をJSONファイル名に使う。同名画像でも別パスなら別データとなり、画像の移動・改名後は自動では引き継がない。

番号確定・追加・チェック変更時に自動保存し、ステータスに［保存済み］を表示する。保存前に同一フォルダーの一時ファイルへ書き込み、ディスクへFlushしてから置換する。直前のJSONは一意な `.bak` 名で保持する（変更回数に応じて増える）。原本画像とPhase 1 JSONは変更しない。

保存内容はschema版、元画像の絶対パス・ピクセル寸法・ファイルサイズ・UTC更新日時、各レコードの固定ID・番号・bbox・信頼度・手動由来・修正済み・済み状態。元のOCR番号とbboxも別に残し、将来の明示的なOCR結果統合に備える。現時点では再OCRや自動統合を行わず、保存済みの全レコードを優先復元する。

画像の寸法・ファイルサイズ・更新日時が変わった場合、または保存JSONが不正な場合は警告して適用せず、既存OCR結果へ戻る。古い保存ファイルは次の保存時にもバックアップへ残る。画像の更新検出はこれらのメタデータ比較であり、内容ハッシュによる検出ではない。

保存失敗時はエラーと［未保存］を表示して編集内容をメモリに保持する。次の変更・画像切替・終了時に再試行し、未保存のまま画像を切り替える／終了する場合は破棄確認を行う。起動時の前回画像自動復元は行わないため、同じ画像を開いて保存内容を復元する。

既存OCRがない画像でも［番号追加］を使用できる。OCRを実行することはない。25%縮小画像キャッシュは追加していない。

再ビルド：`./Build-Viewer.ps1`。回帰確認：`dotnet run --project Viewer.Checks/AF.DecalFinder.Checks.csproj -c Release -- W:\dev\AF-DecalFinder`。保存テストは `viewer-checks/` 内の専用キャッシュで行い、通常の保存データと分離する。

### 描画性能：原因と改善

アプリ側はGDI+ `Graphics.DrawImage` を使用し、BitBltやGPU描画ライブラリへの移行は行っていない。1.3.0では右のパンごとに中央も全面Invalidateされ、原本51メガピクセルからのFit描画を繰り返していた。右も毎回全原本を描画元として指定していた。GDI+内部で何画素が処理されたかまでは測定しておらず、画面外の全画素が必ず描画されたとは断定しない。

計測では画像描画が支配的で、MouseMoveは平均約0.05〜0.13ms、オーバーレイは概ね0.1〜1.3ms。パン中のアプリ管理Bitmap生成・破棄とGCは前後とも0であり、BitmapコピーやGCが主因ではなかった。

実装した改善：中央のFit画像を一時メモリへ描画して再利用し、表示範囲枠の旧・新領域だけをInvalidateする。右は25/50/100/200%で補間用余白付きの可視領域を切り出す。切り出しの画素位相を維持し、75/150%は微小な画質差を避けるため全原本指定の経路を残した。高品質補間は維持し、100%かつ整数座標の場合のみ補間を省く。半画素位置では従来どおり補間する。読込時には原本ピクセルをPArgb形式へ一度変換し、両ビューで共有する。
