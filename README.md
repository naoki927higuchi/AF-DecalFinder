# AF-DecalFinder

## 画像クリックによるOCR逆引き（1.4.1・現在版）

[AF-DecalFinder.exe](bin/Release-1.4.1/AF-DecalFinder.exe) を起動する。.NET 9 Desktop Runtimeが必要。

```powershell
& 'W:\dev\AF-DecalFinder\bin\Release-1.4.1\AF-DecalFinder.exe' 'W:\dev\AF-DecalFinder\inputs\600dpi.jpg'
```

- 右画像の検出位置を左クリックすると、固定IDで対応する一覧行を選択し、一覧をスクロールする。右画像の中心・倍率は変えない。OCRの認識番号が間違っていても位置から確認できる。検出漏れ（JSONにbboxがない数字）は逆引きできない。
- 中央画像では検出位置のクリックを優先し、選択と同時に右画像をbbox中心へ移動する。該当なしなら従来どおりクリック位置へ移動する。青い破線枠のドラッグも使用できる。
- 通常クリックは単一選択、Ctrl＋クリックは追加選択（選択済みの行を解除しない）。一覧を隠した状態・別窓でも更新される。検索赤枠は維持し、選択青枠が優先される。
- 押下位置からの最大直線距離が画面上5px以内ならクリック。途中で一度でも超えるとドラッグ扱いになり、開始位置へ戻っても逆引きしない。5pxを超えてから従来のパンを行う。
- 右の判定矩形は画面上5px拡張。中央では短辺の1/4、最大2pxに制限する。矩形内部を優先し、同順位では中心距離が近い候補を選ぶ。中央で上位2候補の中心距離差が2px以下なら選択せず、通常ナビゲーションのみ行う。密集箇所は右で拡大して確認する。
- Enter移動、Ctrl＋A、ドッキング切替、D&D、即時検索は維持。ダブルクリック/F2の編集機能、OCR再解析、永続化は追加しない。

再ビルド：`./Build-Viewer.ps1`。回帰確認：`dotnet run --project Viewer.Checks/AF.DecalFinder.Checks.csproj -c Release -- W:\dev\AF-DecalFinder`。

## Phase 4.1：一覧操作と描画改善（1.4.0）

### 追加操作

- 一覧でEnterを押すと対象bboxの中心へ移動し、倍率は維持する。単一選択ならそのレコード、複数選択なら**選択済みのフォーカス行**を対象とする。Ctrl＋矢印でフォーカスを移せる。複数選択中に未選択行へフォーカスがある場合は移動しない。画像端は従来のパン制限を適用する。
- 通常の選択変更やCtrl＋Aでは移動しない。ダブルクリックとF2は将来の編集用に予約し、移動・編集とも実行しない。
- ［一覧を切り離す］で同じListViewをモードレス別窓へ移し、左ペインを折りたたむ。［一覧を戻す］または別窓の×で左端へ戻し、以前の幅を復元する。別窓は移動・リサイズ可能。
- ［一覧表示］OFFは、ドッキング中なら左ペイン、フローティング中なら別窓を隠す。ONで同じ状態へ戻す。OFF中は切替ボタンを無効にする。選択、フォーカス行、検出ID、検索赤枠、選択青枠は保持する。
- 画像切替は従来どおり検索・選択を解除し、同じ一覧へ新しい検出レコードを設定する。JSONの場所は実行フォルダー内の `results/600dpi.json` 固定。

### 描画性能：原因と改善

アプリ側はGDI+ `Graphics.DrawImage` を使用し、BitBltやGPU描画ライブラリへの移行は行っていない。1.3.0では右のパンごとに中央も全面Invalidateされ、原本51メガピクセルからのFit描画を繰り返していた。右も毎回全原本を描画元として指定していた。GDI+内部で何画素が処理されたかまでは測定しておらず、画面外の全画素が必ず描画されたとは断定しない。

計測では画像描画が支配的で、MouseMoveは平均約0.05〜0.13ms、オーバーレイは概ね0.1〜1.3ms。パン中のアプリ管理Bitmap生成・破棄とGCは前後とも0であり、BitmapコピーやGCが主因ではなかった。

実装した改善：中央のFit画像を一時メモリへ描画して再利用し、表示範囲枠の旧・新領域だけをInvalidateする。右は25/50/100/200%で補間用余白付きの可視領域を切り出す。切り出しの画素位相を維持し、75/150%は微小な画質差を避けるため全原本指定の経路を残した。高品質補間は維持し、100%かつ整数座標の場合のみ補間を省く。半画素位置では従来どおり補間する。読込時には原本ピクセルをPArgb形式へ一度変換し、両ビューで共有する。

**最終の同条件計測（2026-10-30）**：7783×6579px JPEG、32インチ4K相当の3840×2160pxレイアウト、描画面各1838×2016px、検索49＋全181件選択、各30更新×3反復。下表は右パンのイベント処理から両ビュー描画完了までの平均・P95。実コードをオフスクリーンGDI+へ描くハーネスで、OSの入力待ち行列や表示遅延を含む実FPS測定ではない。

|倍率|更新平均 ms（前→後）|更新P95 ms（前→後）|
|---|---|---|
|25%|368.25 → 146.88|419.07 → 207.44|
|50%|309.67 → 73.21|389.31 → 104.89|
|100%|254.19 → 41.14|304.72 → 62.40|
|200%|233.45 → 31.48|315.29 → 46.40|

中央枠ドラッグでも平均349.73→144.64、293.56→71.73、233.32→38.21、252.47→31.04msへ短縮した。描画回数は30更新につき各ビュー30回から中央29回・右30回で、回数削減より1回の画像描画軽量化が主な効果。CPU時間/更新は短縮したが、待機なしの連続投入なので全CPU比は前後とも概ね3%（32論理CPUの約1コア分）。Private Bytesは約386〜387MiBから400〜401MiBへ増加した。約14MiBの中央描画用Bitmapとの交換条件になる。

**25%の大型表示は改善後も約147msで、滑らかさの課題が残る。** 75/150%は画質検証のみで速度を実測していない。全体の低倍率表示をさらに軽くする場合は、画素位相を維持できる縮小画像/タイルの再利用を別途検証する余地がある。GPU移行は今回行わない。

全8条件の平均/P95 OnPaint、画像・overlay・MouseMove時間、CPU・メモリ・GC・再描画数は [計測表](Performance/MEASUREMENTS.md)、再現方法と測定の限界は [性能検証README](Performance/README.md) を参照。初期のDPI変換不具合を含む試行は評価から除外して別名保存し、上表は修正後に取り直した結果のみ。

### 操作

- 左はOCR番号一覧、中央は全体画像、右は拡大画像。初期一覧幅は約150px、画像2ペインは残りを等分。2本のスプリッターをドラッグして幅を変える。
- ［一覧表示］をOFFにすると一覧と左スプリッターを隠す。ONで以前の幅を復元する（ウィンドウが狭い場合は収まる幅に制限）。非表示中も選択は保持する。
- 一覧は番号の数値順、同番号はY→X順。`04`と`4`の表記や重複検出をそのまま保持する。Ctrl＋クリックで個別追加・解除、Shift＋クリックで範囲選択、Ctrl＋Aで全181件選択、Escで選択解除。選択した全検出を青い実線枠で示す。
- 中央はサイズ変更に合わせて常時Fit。画像内の左クリックで右ビューの中心を指定する。青い破線枠は右の表示範囲で、枠内をドラッグするとリアルタイムに右が追従する。
- 右は25% / 50% / 75% / 100% / 150% / 200%を選択。初期100%は原本1px＝描画先1px。倍率変更・リサイズで画像上の中心を維持する。画像端では必要に応じて中心を制限し、画像が領域より小さい軸は中央配置する。左ドラッグでパンする。倍率はドロップダウンで操作する。
- 検索は1文字ごとの完全一致で、全ヒットを両ビューに赤枠表示する。クリック・フォーカス取得時に検索文字を全選択するので、次の番号をそのまま入力できる。空欄で赤枠のみ解除。検索・一覧選択では自動移動しない。
- 選択の青枠は赤枠より優先。赤枠・青枠・表示範囲枠は塗りつぶしなし、画面上約2px。全体ビューで小さすぎる番号は、中央をクリックして右で確認する。
- JPG/JPEG/PNGのファイル選択・D&Dに対応。画像切替で検索・選択を解除し、右を100%・画像中心に戻す。実行フォルダーの `results/600dpi.json` を再読込し、欠落・不正・寸法不一致なら空一覧・検索不可とする。画像自体の読込失敗時は既存表示を保持する。
- 対応JSONの場所は従来どおり固定。画像ごとにJSONを探索する機能はない。同じ寸法の別画像は識別できないため、今回のJSONに対応するテムジン原本を使用する。

## 構成

- `prepare_inputs.py`：ZIP内の唯一のJPEGを無変換で抽出し、既存原本との不一致を拒否。
- `benchmark.py`：ネイティブTesseract実行・原本座標への変換・速度/メモリ計測。正解データは一切読まない。
- `ground_truth.json`：OCR開始前に目視作成した38件。`make_ground_truth.py`に手入力した番号・矩形を保存。`evaluation_sources`に領域・位置合わせの記録を保存。
- `evaluate.py`：位置による1対1照合とCSV集計。
- `report.py`：今回の選定設定と実測値を使った報告書・確認画像の再生成。結論文はこの入力・今回の実測に固有。
- `verify.py`：入力不変性と出力契約の検証。
- `environment.json`：今回の実測環境。別PCで再実験する場合は環境・結論を更新し、今回の数値と区別する。

選定に使った38件での評価であり、未使用図面への汎化性能は未検証。C# WinFormsへの組込み、C#バインディングの選定、GUI・キャッシュ等は対象外。
