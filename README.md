# AF-DecalFinder

## 1.7.0：OCR自動実行・画像別キャッシュ統合（現在版）

起動：[AF-DecalFinder.exe](bin/Release-1.7.0/AF-DecalFinder.exe)。画像を開く／D&D／履歴／起動時復元の全経路で、有効な画像別キャッシュがあれば即復元し、なければ自動解析する。以前の固定Phase 1 JSONフォールバックは製品経路から除去した。

### OCR実装方式と実行条件

C#から別プロセスのPythonワーカーを非同期起動する方式を採用。Phase 1 `benchmark.py` を変更せずビルド先へコピーし、`circle_psm7_wide` の丸ラベル候補・切出し・マスク・横3倍/縦2倍LANCZOS・白余白10px・PSM7・数字ホワイトリスト・重複排除を同じ関数で実行する。元画像の画素座標で返す。IDは新規OCRでは `ocr-0001` 等を採番し、その後の編集でも維持する。Phase 1 IDとの一致は要求せず、番号とbboxを比較した。

|方式|再現性・工数|配布条件|判断|
|---|---|---|---|
|Pythonワーカー + tesserocr/OpenCV|Phase 1の実コードを再利用でき、移植差が最小|Pythonと同じネイティブ依存物が必要|今回採用|
|C# + native Tesseract/OpenCV|丸検出・Pillowリサイズ・座標丸めの移植検証が必要|Python不要だがネイティブDLL/モデルの配置は必要|今回は不採用|

このPCの構成：Python 3.12、Pillow 12.3.0、tesserocr 2.12.0 / Tesseract 5.5.3、OpenCV headless 5.0.0.93、NumPy 2.5.4、psutil 7.2.2、Phase 1のeng.traineddata。OCRエンジンやモデルをネットワークから取得する処理はない。

`./Build-Viewer.ps1` でReleaseとOCR実行フォルダーを用意する。`Build-Ocr.ps1` は既存 `.deps`、`tessdata`、未変更の `benchmark.py` と `Ocr/worker.py` を `bin/Release-1.7.0/Ocr/` へコピーし、Python絶対パスを同フォルダーの `runtime.json` に記録する。既定PythonはこのPCの `%USERPROFILE%\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe`。別Pythonなら `./Build-Ocr.ps1 -Python 'C:\path\python.exe'` で再設定する。現在のネイティブ依存物に合わせて **64bit Python 3.12とPillowが別途必要**。EXEだけのコピーではOCRできない。.NET 9 Desktop Runtimeも必要。別PC向けインストーラーや公開配布物は今回作成していない。

### キャッシュと解析中の操作

- `%LOCALAPPDATA%\AF-DecalFinder\Cache\` を継続使用。絶対パスの大文字化UTF-8 SHA256をファイル名とし、内部のパス・UTC最終更新日時・Width/Height・ファイルサイズを検証する。内容が同じでも更新日時が違えば再解析する。
- 有効な旧版キャッシュは形式を変えず優先復元する。修正番号・元OCR値・固定ID・手動追加・済みチェックを維持し、画像間で共有しない。
- 無効キャッシュは解析前に `.stale-日時-GUID.json` へ同じバイト列を退避する。退避できなければ上書きしない。新解析成功時は一時ファイルをFlush後、File.Replace（旧内容の `.bak` を保持）で安全に保存する。旧編集内容の座標引継ぎは行わない。解析失敗でも旧ファイルを削除しない。
- OCR中は待機カーソル、空一覧、検索/編集/チェック/番号追加無効。再描画・パン・倍率・別画像読み込みは可能。画像decode自体は従来の同期処理のため、大画像を開く最初の短時間は待機がある。
- 画像切替時は旧ワーカーを取消し、さらに世代番号で遅い結果を拒否する。終了時も取消す。原本を処理中に更新した場合は結果を適用せず開き直しを案内する。
- 0件は成功として保存。解析失敗は下部ステータスに原因を表示し、長い内容はツールチップで確認できる。画像閲覧を継続でき、カーソルを戻す。保存失敗は既存の未保存エラーを表示する。
- 番号・ID・confidence・bboxの不正なOCR行は除外し、画像寸法不一致や壊れた出力は解析エラーにする。数字限定でも図形や日本語の一部を数字として誤検出し得る。

## 1.6.2：画像別OCR参照の修正・アプリアイコン（旧版の記録）

追加入力画像でも検証済み：[8画像の寸法・DPI・表示結果](INPUT-IMAGE-CHECKS.md)。追加6枚を含め、専用設定で画像切替・25/50/100/200%・端へのパン・原本不変を確認。再実行は `dotnet run --project Viewer.Checks/AF.DecalFinder.Checks.csproj -c Release -- W:\dev\AF-DecalFinder --inputs`。製品コードと版数は変更していない。

[AF-DecalFinder.exe](bin/Release-1.6.2/AF-DecalFinder.exe) を起動する。

### 原因と修正

1.6.1の `MainForm.jsonPath` は実行フォルダーの `results/600dpi.json` に固定されていた。`OpenImage()` は `store.Load(identity)` で画像別キャッシュを探し、ない／無効なら `candidate ??= OcrCatalog.Load(jsonPath)` を無条件実行していた。その後の寸法チェックで、ガンダム5009×5809とテムジンJSON7783×6579の不一致警告になっていた。同じ寸法の別画像では誤流用され得る経路でもあった。

画像切替時は既にcatalogをnull、LVを空にし、両ImageViewControl.SetImageでdetections/highlights/selectionsを空にしていた。今回の原因は前画像の配列の残留ではなく、固定JSONへのフォールバックだった。

1.6.2では `Phase1Seed.Load()` がPhase 1 manifestに記録された600dpi原本のSHA256と寸法を確認し、一致したときだけ固定JSONを初期データとして読む。ファイル名・寸法だけでは判定しない。原本と同一バイトのコピーは利用できるが、再圧縮や画像内容を変更したファイルは、対応する編集キャッシュがなければ未解析となる。このハッシュは初期OCRとの対応確認だけに使用し、画像履歴のキーには使用しない。

キャッシュも対応初期データもない画像は画像だけを表示し、一覧を空、検索不可にする。番号の手動追加は既存機能として利用できる。OCRは実行しない。

### 画像別キャッシュ

保存先は `%LOCALAPPDATA%\AF-DecalFinder\Cache\`。`EditStore.PathFor()` が `Path.GetFullPath(path).ToUpperInvariant()` のUTF-8 SHA256をファイル名にする。読み込み時はキャッシュ内の絶対パス（大文字小文字を区別しない）・UTC最終更新日時・Width/Height・ファイルサイズを `ImageIdentity.Matches()` で照合する。固定ID、修正番号、手動追加、済み状態はその画像のレコードとして独立して保持する。

キャッシュ形式や保存方式は変更していない。無効データは警告して適用せず、ファイルを自動削除しない。次の編集保存で既存ファイルを置換するときも従来のバックアップを保持する。画像を戻せばそのパスの有効な作業データを復元する。

- 左はOCR番号一覧、中央は全体画像、右は拡大画像。初期一覧幅は約150px、画像2ペインは残りを等分。2本のスプリッターをドラッグして幅を変える。
- ［一覧表示］をOFFにすると一覧と左スプリッターを隠す。ONで以前の幅を復元する（ウィンドウが狭い場合は収まる幅に制限）。非表示中も選択は保持する。
- 一覧は番号の数値順、同番号はY→X順。`04`と`4`の表記や重複検出をそのまま保持する。Ctrl＋クリックで個別追加・解除、Shift＋クリックで範囲選択、Ctrl＋Aで全181件選択、Escで選択解除。選択した全検出を青い実線枠で示す。
- 中央はサイズ変更に合わせて常時Fit。画像内の左クリックで右ビューの中心を指定する。青い破線枠は右の表示範囲で、枠内をドラッグするとリアルタイムに右が追従する。
- 右は25% / 50% / 75% / 100% / 150% / 200%を選択。初期100%は原本1px＝描画先1px。倍率変更・リサイズで画像上の中心を維持する。画像端では必要に応じて中心を制限し、画像が領域より小さい軸は中央配置する。左ドラッグでパンする。倍率はドロップダウンで操作する。
- 検索は1文字ごとの完全一致で、全ヒットを両ビューに赤枠表示する。クリック・フォーカス取得時に検索文字を全選択するので、次の番号をそのまま入力できる。空欄で赤枠のみ解除。検索・一覧選択では自動移動しない。
- 選択の青枠は赤枠より優先。赤枠・青枠・表示範囲枠は塗りつぶしなし、画面上約2px。全体ビューで小さすぎる番号は、中央をクリックして右で確認する。
- JPG/JPEG/PNGのファイル選択・D&Dに対応。画像切替で検索・選択を解除し、右を100%・画像中心に戻す。実行フォルダーの `results/600dpi.json` を再読込し、欠落・不正・寸法不一致なら空一覧・検索不可とする。画像自体の読込失敗時は既存表示を保持する。
- 対応JSONの場所は従来どおり固定。画像ごとにJSONを探索する機能はない。同じ寸法の別画像は識別できないため、今回のJSONに対応するテムジン原本を使用する。

## 構成

- `prepare_inputs.py`：ZIP内の唯一のJPEGを無変換で抽出し、既存原本との不一致を拒否。
- `benchmark.py`：ネイティブTesseract実行・原本座標への変換・速度/メモリ計測。正解データは一切読まない。
- `ground_truth.json`：OCR開始前に目視作成した38件。`make_ground_truth.py`に手入力した番号・矩形を保存。`evaluation_sources`に領域・位置合わせの記録を保存。

- `report.py`：今回の選定設定と実測値を使った報告書・確認画像の再生成。結論文はこの入力・今回の実測に固有。
- `verify.py`：入力不変性と出力契約の検証。
- `environment.json`：今回の実測環境。別PCで再実験する場合は環境・結論を更新し、今回の数値と区別する。

選定に使った38件での評価であり、未使用図面への汎化性能は未検証。C# WinFormsへの組込み、C#バインディングの選定、GUI・キャッシュ等は対象外。
